# Site videos with yt-dlp (YouTube, Facebook, Instagram, X, TikTok, Vimeo…)

**Goal:** a video on a site that doesn't serve plain files or standard HLS (YouTube, Facebook, Instagram, X, TikTok, Vimeo, Dailymotion, Twitch clips, Reddit) can be downloaded with one click.
- ODM receives the **page address** and runs the external tool **yt-dlp**, which works out the video and audio and merges them into an `.mp4` using FFmpeg.
- It works like FFmpeg: an external program, never bundled.

**Constraints:**
- These still hold:
  - Plan 3 Global Constraints: privacy (no cookie values in logs, URLs redacted), identity values only from `odm_core::ids` / `ids.ts`, the confirm-dialog flow, and the UI copy rules.
  - Nothing is sent without a click.
- yt-dlp and FFmpeg run with `CREATE_NO_WINDOW` and `kill_on_drop(true)`.
- **Gates:**
  - Rust: fmt, clippy `-D warnings` and workspace tests.
  - App: `pnpm check` 0/0, `pnpm test` and `pnpm build`.
  - Extension: `pnpm check`, `pnpm test` and `pnpm build`.
- Commit per task with the `Co-Authored-By` line. Do not push.

## Task 1: engine, protocol and app (Rust)

**Interfaces:**


**`find_ytdlp` order:**
1. `cfg.ytdlp_path` if it is a file.
2. If `ytdlp_search`:
   - `yt-dlp.exe` on `PATH`;
   - `%LOCALAPPDATA%\Microsoft\WinGet\Links\yt-dlp.exe`;
   - the first `%LOCALAPPDATA%\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_*\yt-dlp.exe`.
3. Otherwise `None`.

**`build_args`** (exact; the order matters for tests):
```
--newline --no-playlist --no-colors --continue --no-mtime
-f bv*+ba/b --merge-output-format mp4
-o <tmp>\%(title).150B [%(id)s].%(ext)s
--progress-template download:ODMP %(progress.downloaded_bytes)s %(progress.total_bytes)s %(progress.total_bytes_estimate)s %(progress.speed)s %(progress.eta)s
--print after_move:ODMFILE %(filepath)s
[--ffmpeg-location <ffmpeg>]                 (when FFmpeg was found; same lookup as HLS)
[--js-runtimes node:<node>]                  (when node was found)
[--limit-rate <bytes>]                       (when limit_bps > 0)
[--add-header <Name>:<Value>]...             (each stored header, Cookie included)
<page_url>
```

**`parse_line`:**
- `ODMP a b c d e`: a downloaded; total = b if numeric, else c if numeric; speed d; eta e. Non-numbers (`NA`, `None`) become `None`. Floats are truncated.
- Lines starting with `[Merger]`, `[VideoConvertor]` or `[FixupM3u8]` → `Merging`.
- `ODMFILE <path>` → `Output`.
- Anything else → `Other`.

**`ByteCounter`:** when `downloaded` drops below the last value, the last stream's total (or last value) joins a base. It returns `(base + downloaded, total.map(|t| base + t))`.

**`run_site`:**
1. Probing → find yt-dlp. If it is missing, fail with the exact message `"yt-dlp not found — install it or set its path in Settings."`.
2. Create the temp dir. Spawn with the stored headers, reading stdout and stderr line by line (keep the last 20 stderr lines). Move to Downloading on the first Progress, and emit `Progress` events at `progress_interval`: bytes, total, speed, eta, `chunks: []`, `segments: None`. Move to Merging on `Merging`.
3. Cancel → kill the process and return Stopped. yt-dlp's `--continue` resumes `.part` files on the next run.
4. Exit code 0 with an `Output` path → `place_final` it into the save dir (same unique-name logic and Mark of the Web as HLS), set the size, delete the temp dir → Completed.
5. Non-zero exit → fail with `"yt-dlp could not download this video:\n" + stderr tail`. The temp dir stays.

**Manager:**
- `launch` dispatches `"site"` → `run_site`.
- cancel and remove of an unfinished site download delete its temp dir (like HLS).
- `add_site` filename:
  - the request filename (sanitised, `.mp4` enforced);
  - else `page_title` sanitised with the HLS title sanitiser + `.mp4`;
  - else `video.mp4`.
  
  The record's `url` is `page_url`. The final name comes from yt-dlp's output file name (keep the title-based name the user saw if the user locked a filename in the confirm dialog; otherwise use yt-dlp's base name).

**appcore:**
- **`ipc.rs`** handles `ADD_PAGE`, the same as `ADD_STREAM`:
  - parse;
  - headers = `payload.headers` + `Referer` = `page_url` + `Cookie`, then `normalize_headers`;

- **Settings:**

**Test support:**
- A fake yt-dlp binary `crates/odm-testserver/src/bin/fake-ytdlp.rs`, test-only.
- It finds the `-o` template's directory, writes `video [abc].mp4` there with 300 000 pattern bytes, and prints:
  - 3 `ODMP` lines for stream 1 (total 200000);
  - then 2 for stream 2 (total 100000);
  - then `[Merger] Merging formats`;
  - then `ODMFILE <full path>`.
- It exits 0.
- Environment controls:
  - `FAKE_YTDLP_FAIL=1` prints 25 lines to stderr and exits 1;
  - `FAKE_YTDLP_SLOW=1` sleeps 200 ms between lines;
  - `FAKE_YTDLP_ARGS=<file>` writes argv (one per line) to that file.
- Tests locate it with `env!("CARGO_BIN_EXE_fake-ytdlp")`. They live in `odm-testserver`'s own tests, or are reachable from engine tests by making odm-engine dev-depend on odm-testserver (it already does) and building the bin. If `CARGO_BIN_EXE_` isn't visible across crates, locate the binary next to the test executable (`target/<profile>/fake-ytdlp.exe`) after `cargo build -p odm-testserver --bins`, and document that.
